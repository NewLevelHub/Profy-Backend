# Profi → «Акинатор»: пакет для разработки. С чего начать

Проектирование закончено. Это пакет для передачи агенту (Claude Code в VS Code). Ниже — что в каком файле и в каком порядке читать.

## Порядок чтения для агента

1. **profi_akinator_prompt.md** — стартовый промпт/ТЗ. Читать первым: суть задачи, что меняем, жёсткие правила, порядок фаз, как работать в репозитории.
2. **profi_akinator_svod.md** — полная выжимка всех решений и правил (14 разделов). Главный справочный документ.
3. **profi_svod_addendum.md** — дополнение к своду: сквозной принцип «предлагаем, не навязываем» + разрешатель кластера. Читать сразу после свода.
4. **profi_axes_phase1.md** — **ЕДИНСТВЕННЫЙ источник правды по осям**: финальные 24 оси (A5+B6+C3+D7+E3), формула апдейта, критерий остановки, правило формата. Если где-то в других файлах встретятся другие названия осей (`B_analyze`, `B_hands`, `C_body`, `D_persistence`, `E_subject_*`) — это следы раннего черновика, игнорировать; в этом файле есть таблица соответствия.
5. **profi_full_catalog.md** — 67 профессий с профилями по осям + 39 проблемных пар с типами лечения. Это seed-контент для Фазы 2.
6. **profi_questions_mvp.md** — банк вопросов, ядро (q01–q24).
7. **profi_questions_full_addon.md** — банк вопросов, добавка (q25–q41): покрытие всех веток + разрешатели.

## Вспомогательные (не обязательны агенту)

- **profi_professions_check.md** — ранняя проверка осей на 12 профессиях (история решений). **Оси в нём устаревшие** — актуальные только в файле 4.
- **gemini_prompts.md** — промпты, которыми генерировали оси/профессии (для справки).

## Статус контента (важно)

- Оси — финальные.
- Каталог и профили — черновик, **требует вычитки человеком** (много осторожных весов).
- Вопросы — покрытие полное (все ветки и пары), но **черновик**: веса и сценарии на вычитку; вопросы q07–q13 определены по смыслу, свести в единый вид.
- Настоящая проверка покрытия — в Фазе 2 (прогон вопросов против всех профилей).

## Что делать агенту

Начать с **Фазы 1**: спроектировать таблицы БД (дерево профессий с профилями, вопросы с весами по осям, сессия с верой по листьям), обратимые миграции. Оси не переизобретать — брать из файла 4. Старый код не удалять, пока замена не готова и не покрыта тестами. В спорных местах — спрашивать, не додумывать.

Фазы: 1 БД/оси → 2 контент+пайплайн → 3 движок+тесты → 4 диалог+логи → 5 отчёт+удаление старого → 6 симуляции/разрешатель (после запуска).
