# Profi-акинатор — Фаза 1: каталог осей и формула (черновик к ревью)

Статус: **проект к ревью, не финал.** Оси и формула решены по форме; точные веса (профили профессий, β, пороги) ставятся по калибровке на реальных детях. Набор осей — вход в Фазу 2: после того как профили проставлены всем профессиям, проверяем слипания и дотачиваем.

Шкала значений оси в профиле профессии: целые **−2 … +2**
(−2 сильно против / −1 против / 0 нейтрально / +1 подходит / +2 сильно подходит).
Для большинства профессий большинство осей = 0.
Вклад варианта ответа: знаковые небольшие целые (−2 … +2) по нескольким осям.

---

## Семейство A — Ориентация (с чем работаешь). Формат: ПРЯМОЙ. Глубина: 0–1.

Самый грубый разрез каталога. Профессия может быть высокой по нескольким.

| ось | низко | высоко | пример высокой профессии |
|---|---|---|---|
| A_people | не про людей | работа с/для людей напрямую | учитель, психолог, врач |
| A_living | не про живое | животные, природа, тело, биология | ветеринар, эколог, тренер |
| A_things | не про предметы | техника, руками, строить, чинить | механик, строитель, столяр |
| A_data | не про данные | числа, системы, логика, код | аналитик, разработчик, бухгалтер |
| A_ideas | не про творчество | создавать, эстетика, выражение | дизайнер, режиссёр, архитектор |

## Семейство B — Модальность (что делаешь, глагол работы). Формат: СМЕШАННЫЙ (по глубине). Глубина: 1–3.

Сюда легли развилки из симуляций.

| ось | смысл | развилка из симуляций |
|---|---|---|
| B_create | создавать новое | |
| B_analyze | понимать, находить закономерности, диагностировать | |
| B_care | заботиться, лечить, поддерживать конкретного человека | **«лечить»** (лечить vs учить) |
| B_develop | развивать, учить, растить других | **«учить»** (лечить vs учить) |
| B_organize | координировать, вести, управлять | «вести» (помогать vs вести) |
| B_perform | выступать, представлять, быть на виду | «быть в центре» (помогать vs быть в центре) |
| B_hands | делать/чинить руками (vs абстрактно) | ручной vs абстрактный труд |

## Семейство C — Канал (через что воздействуешь). Формат: СМЕШАННЫЙ. Глубина: 3+.

Тонкие оси, активны в основном в ветках «учить/заботиться». Для прочих профессий = 0.

| ось | смысл | развилка |
|---|---|---|
| C_body | через тело, движение, физический навык | **«тело»** (предмет vs тело vs чувства) |
| C_subject | через знание, предмет, содержание | **«предмет»** |
| C_emotion | через чувства, психологию, отношения | **«чувства»** |

## Семейство D — Темперамент и мотивация. Формат: СИТУАТИВНЫЙ (всегда). Глубина: 2+.

Меряется только ситуациями — прямой вопрос дал бы социально желательный ответ.

| ось | низко | высоко | из симуляций |
|---|---|---|---|
| D_persistence | «и так сойдёт» | доводить, доделывать до чистоты | «переделаю кривую стену» |
| D_result_process | процесс, стабильность | результат, победа, максимум | «готовить к результату» |
| D_risk | безопасность, предсказуемость | комфорт с риском, высокие ставки | |
| D_autonomy | в команде | самостоятельно, один | |
| D_structure | свобода, без рамок | правила, процедура, порядок | «творчество в рамках правил» (идеи+D_structure) |
| D_pace | стабильно, рутина | динамично, разнообразно | |

## Семейство E — Практика (факты-ограничения). Формат: ПРЯМОЙ. Глубина: любая.

| ось | смысл | из симуляций |
|---|---|---|
| E_study_length | готовность к долгой учёбе | «5–6 лет учёбы — нормально» |
| E_physical | переносимость физической нагрузки | |
| E_math | прикладная / абстрактная / никакая | «математика, когда видно зачем» |
| E_subject_bio / E_subject_hum / … | предметные склонности | «биология — да, гуманитарное — тяжело» |

## Как комбинации осей выражают тонкие типы (проверка выразительности)

- Архитектор = A_ideas+2, A_things+1, A_data+1, D_structure+2, E_study_length+1 → отличается от **свободного художника** (A_ideas+2, D_structure−1) именно по D_structure.
- Спортивный тренер = A_people+1, A_living+1, B_develop+2, C_body+2, D_result_process+2 → отличается от **учителя-предметника** (B_develop+2, C_subject+2) по каналу, от **реабилитолога** (B_care, C_body) по care-vs-develop и result-vs-process.

Если два листа совпадают по ВСЕМ осям — не хватает оси, добавить в Фазе 2.

## MVP-подмножество осей (~12–14)

Для старта: всё семейство **A** (5), ядро **B** (create, analyze, care, develop, organize — 5), ядро **D** (persistence, result_process, autonomy — 3), из **E** (study_length + math). Семейства **C**, B_perform/B_hands, хвост D и E — добавляются при углублении дерева.

## Правило формата (сводно)

Формат вопроса = функция(семейство оси, глубина):
- A, E → прямой, всегда.
- D → ситуативный, всегда.
- B, C → смешанный: наверху прямой, на тонких развилках ситуативный.
- Глубина 0–1 → только прямые/широкие; ситуации с глубины 2+.

## Правило старта (анти-жадность)

Первые ~3 вопроса — широкие прямые по **разным семействам** (A_ориентация → E_предметы/склад → ещё одна ось A/E), не углубляя первый ответ. Сужение и ситуации — только после того, как видно пересечение сигналов.

## Формула апдейта (вид решён, магнитуды — калибровка)

- Профиль листа L: вектор по осям (−2…+2). Вклад ответа A: вектор по осям.
- match(A, L) = Σ_ось A[ось]·L[ось] (скалярное произведение).
- Апдейт: `log belief(L) += β · match(A, L)`, затем softmax-нормировка (Σ belief = 1).
- Выбор вопроса: минимизируем ожидаемую энтропию belief после ответа (P(вариант) усредняем по текущему belief). Та же match-функция.
- «Не знаю» → вклад 0.
- Старт: β ≈ 0.7. Тюнится по логу.
- RIASEC-fix держится, потому что нормировка по листьям (не по осям) и match симметричен.

## Критерий остановки (форма решена, числа — калибровка)

- **Одна профессия**, если top-1 > T И top-1 ≥ M × top-2.
- Иначе **группа** top-k, пока накопленная вероятность ≤ ~70%, но k ≤ 3.
- Старт: T ≈ 0.45, M ≈ 1.5, k ≤ 3. Консервативно — лучше группа, чем ложная уверенность.
- Плюс потолок вопросов по возрасту (junior ниже) как предохранитель; упор в потолок без схождения → показываем группу (валидный исход).

---

## Два риска для калибровки

1. **Независимость осей.** Лог-линейное накопление предполагает, что оси не дублируются. Коррелирующие оси (напр. A_data и E_math abstract) → двойной счёт. Проверить на реальных профилях.
2. **Разделяют ли оси профессии.** Настоящая проверка — не список, а профили. Проставить профили всем 50–60 профессиям (Фаза 2), найти слипания, дот点чить оси. Заложить этот цикл сразу.
