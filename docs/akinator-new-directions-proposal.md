# Предложение: новые направления акинатора (на основе базы вузов Алматы)

Задача для отдельного чата — не часть калибровочной сессии
(`akinator-calibration-backlog.md`), не начинайте её в контексте калибровки.

## Контекст

- `scripts/seed_akinator_content.py` сейчас содержит **52 специальности**
  (`SPECIALTIES`) + **6 explore-узлов** (`EXPLORE_NODES` для junior/middle
  возрастов) + 13 секций (`SECTIONS`). Было 38 специальностей, недавно (пометка
  в коде "добавлены 2026-07") добавили 14 новых: it-development,
  artificial-intelligence, engineering-architecture, science-research,
  ecology-nature, medicine-biology, psychology-pedagogy,
  marketing-advertising, business-entrepreneurship, finance-economics,
  project-management, law-public-administration, design-digital-art,
  media-journalism.
- Каждая специальность — это словарь с полями `slug`, `name`, `label_junior`,
  `section`, `description`, `profile` (веса по 24 осям из `app/core/axes.py`,
  диапазон -2..+2), `professions` (список конкретных профессий-примеров),
  `subjects_required` (JSONB, предметы ЕНТ для readiness-квиза).
- Сверил все `direction_slugs`, используемые в
  `scripts/seed_almaty_universities.py` (курируемый словарь программ по
  вузам), против текущих 52+6+13 — **пробелов там нет**, всё замаплено.
- НО сырые данные `scripts/almaty_universities_data.py` (несокращённый скрап
  40+ вузов Алматы, `ALMATY_UNIVERSITIES`, поле `specialties` → список групп
  `{"group": ..., "programs": [...]}`) содержат реальные программы, которые
  пока никуда не мапятся — см. список ниже.

## Что нужно сделать

1. Решить, какие из направлений ниже добавлять (не обязательно все — можно
   начать с "явных пробелов").
2. Для каждого выбранного направления спроектировать `profile` (веса по
   осям `app/core/axes.py`) по той же методологии, что и остальные 52 —
   см. `docs/akinator-calibration-backlog.md` для примеров рассуждений
   (например, как выбирались оси для `data-science`, `psychologist`,
   `pilot`). Важно: НЕ копировать оси бездумно — сверяться с `axes.py`,
   искать реальный психологический/деятельностный смысл направления.
3. Добавить резолверы (`resolves_pair`) там, где новое направление рискует
   слиться с существующим соседом по секции (см. методологию раунда 16 —
   искать оси, где НИ ОДНОЙ противоположной нет между соседями).
4. Прогнать `scripts/calibration_simulate.py --census --runs 100` (x2 для
   проверки стабильности) — новые направления добавляют шум в существующую
   калибровку, нужно перепроверить весь census заново, не только новые
   специальности.
5. Проверить `seed_almaty_universities.py` — возможно, после добавления
   новых направлений часть программ из `almaty_universities_data.py`,
   которые раньше грубо мапились на ближайшую специальность, стоит
   перепривязать на новую, более точную.

## Кандидаты — явные пробелы (крупные отрасли, много программ)

1. **Нефтегаз / горное дело / геология** — "Нефтегазовое дело", "Нефтяная
   инженерия", "Геология и разведка месторождений полезных ископаемых",
   "Урановое дело". Крупнейшая отрасль РК, сейчас вообще не представлена.
2. **Энергетика** — "Электроэнергетика", "Теплоэнергетика",
   "Энергообеспечение сельского хозяйства". Сейчас размазано по
   `mechanical-engineer`, хотя это отдельная крупная сфера.
3. **Международные отношения / регионоведение** — "Международные
   отношения", "Регионоведение". Ничего похожего сейчас нет.
4. **Логистика** — "Транспортная логистика", "Производственная логистика".
   Есть только общий `business-entrepreneurship`/`project-management`,
   логистика как профессия не выделена.
5. **Авиационная техника** (НЕ путать с `pilot`!) — "Техническая
   эксплуатация летательных аппаратов и двигателей", "Обслуживание систем
   авионики", "Наземное радиоэлектронное оборудование аэропортов". `pilot`
   — про полёты, это — про обслуживание техники, разные профессии и разный
   психологический профиль (Motor/Struct-инженерный, не Risk/Focus-лётный).
