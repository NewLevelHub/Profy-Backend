# Формат для догрузки недостающих вузов (A3)

Как вернуть данные, чтобы их можно было завести в базу тем же способом, что уже есть для Алматы/Астаны — без ручной переработки формата.

Два раздела: казахстанские вузы (ниже) и зарубежные (в конце файла) — у них разный формат, потому что источники разные (официальный реестр ОВПО vs курируемые кластеры по профессиям).

## Формат — один объект на вуз (Казахстан)

```python
{
    "slug": "atyrauskiy-universitet-nefti-i-gaza",   # kebab-case латиницей, уникальный
    "ovpo_code": "009",                               # ОБЯЗАТЕЛЬНО — см. таблицу ниже, это canonical-ключ
    "name": "Атырауский университет нефти и газа имени Сафи Утебаева",
    "short_name": "АтырУНГ",
    "aliases": ["АУНГ", "AUNG"],                      # варианты названия, можно []
    "city": "Атырау",
    "country": "Казахстан",
    "website": "https://...",
    "description": "2-4 предложения: год основания, специализация, масштаб, международные связи",
    "location": "Атырау, ул. ...",                     # адрес кампуса, если найдётся
    "specialties_summary": "1 предложение: сколько программ и по каким направлениям в целом",
    "specialties": [
        {"group": "Нефтегазовое дело", "programs": ["Нефтегазовое дело", "Химическая технология"]},
        {"group": "...", "programs": ["...", "..."]}
    ],
    "admission_summary": "1 предложение: общая схема поступления",
    "admission_requirements": [
        "Обязательные предметы ЕНТ: История Казахстана, Математическая грамотность, Грамотность чтения.",
        "Профиль ХХХ: предмет1 + предмет2."
    ],
    "rankings": []   # текстовые упоминания рейтинга, если есть; иначе пустой список
}
```

Поля `slug`, `ovpo_code`, `name`, `city`, `country` — обязательны. Остальное можно оставлять частичным (лучше 5 реальных специальностей, чем 20 придуманных) — данные всегда можно дополнить следующим заходом.

**Как вернуть:** JSON- или Python-список таких объектов, любой порцией (не обязательно все 48 сразу). Файл(ы) можно просто прислать — заведу в БД тем же скриптом, что уже используется для остальных вузов.

## Почему именно так

- `ovpo_code` обязателен, потому что это единственный надёжный ключ, по которому баллы гранта из PDF МОН РК потом автоматически подтянутся к этим вузам — без него пришлось бы повторять ручной мэтчинг по имени, который уже один раз давал потери (см. `docs/ovpo-registry-gap-analysis.md`).
- Формат специальностей (`group` → `programs`) — тот же, что уже отработан на 55 вузах Алматы/Астаны, заводится тем же сид-скриптом без переделки.

# Формат для догрузки зарубежных вузов

Другой источник, другой формат — зарубежные вузы у нас не привязаны к городу/скрейпу, а сгруппированы по кластерам профессий (`scripts/data/universities_92_professions.py`, 14 кластеров, ~92 профессии). Один вуз в кластере = один блок текста, который относится **сразу ко всем профессиям этого кластера** (не к одной специальности), плюс сид-скрипт сам создаёт по одной Program-строке на каждую профессию кластера.

## Формат — один объект на вуз, внутри существующего или нового кластера

```python
{
    "slug": "eth-zurich",                              # kebab-case, уникальный
    "ror_id": "05a28rw58",                              # см. ниже, как искать
    "name": "ETH Zurich",
    "short_name": "ETH Zurich",
    "country": "Швейцария",
    "city": "Цюрих",
    "website": "https://ethz.ch",
    "ranking_label": "#7 (QS World)",                    # текстом; если это глобальный QS/THE World номер — распарсится и в число автоматически
    "description": "2-4 предложения: специализация, престиж, чем известен именно в контексте профессий этого кластера",
    "language": "Немецкий (бакалавриат), английский (магистратура)",
    "cost_text": "~730 CHF в семестр",                    # текстом, диапазон/валюта — это нормально, в число не нужно
    "requirements_text": "Эквивалент Matura; вступительный экзамен ETH; языковой сертификат C1.",
    "grants_text": "Excellence Scholarship & Opportunity Programme — топ-2% потока.",
}
```

**Обязательные поля:** `slug`, `name`, `country`, `city`. `ror_id` — очень желателен (см. ниже почему), `website` — тоже (у 62 из 96 текущих зарубежных вузов его до сих пор нет — не плодить новых пробелов).

## Как искать `ror_id`

Уже есть готовый скрипт `scripts/find_ror_id.py` (использует открытый бесплатный API ror.org):

```
python scripts/find_ror_id.py "ETH Zurich"
python scripts/find_ror_id.py "Nanyang Technological University" --country Singapore
```

Он же обычно отдаёт и официальный `website` — можно брать оттуда же.

## Куда именно вставлять — кластер или профессия

Каждый вуз живёт внутри одного или нескольких кластеров из `CLUSTERS` в `scripts/data/universities_92_professions.py` (уже 14 штук, каждый — набор смежных профессий, например «IT, инженерия данных и ИИ»). Два варианта:

1. **Вуз усиливает существующий кластер** — просто добавить объект в список `"universities"` нужного кластера. Проще всего прислать: «этот вуз — в кластер X» + сам объект.
2. **Нужен вуз под профессию, для которой ещё нет кластера/подходящего вуза** — тогда напиши, под какую профессию (направление) нужен вуз, и я подскажу, попадает ли она в существующий кластер или нужен новый.

## Почему не как у казахстанских

- Нет `ovpo_code` — зарубежные вузы не участвуют в грантовом конкурсе МОН РК, поэтому для них нет и не может быть баллов ЕНТ. Вместо чисел — `requirements_text`/`grants_text` текстом (эссе, рекомендации, языковой сертификат и т.п. — это как раз то, что уже частично автоматически извлекается LLM-ревью в `scripts/generate_program_requirements_content.py`, не нужно дублировать вручную).
- `cost_text` остаётся текстом принципиально — валюта и диапазон разные у каждого вуза, в одно число это осознанно не приводится (см. `docs/university-module-fix-plan.md` A6 — там же обсуждается будущий min/max числовой парсинг, это отдельная, не блокирующая задача).
