# QA — сквозной прогон продукта на казахском (`kk`)

Приёмочный чеклист KZ-601. Цель: `kk`-ученик проходит весь путь и **нигде** не
видит русского текста, i18n-ключа или пустого блока. Единственное допустимое
исключение — админка `/admin/*` (по решению KZ-210 остаётся `ru`-only, в
чеклист не входит).

## Как запускать ручной прогон

`kk` физически отсутствует в `SUPPORTED_LOCALES` / `supportedLngs` до финального
PR KZ-603, поэтому ручной прогон делается на **dev-стенде с временно включённым
`kk`**:

- backend: `app/i18n/__init__.py` → `SUPPORTED_LOCALES = ("ru", "kk")`;
- frontend: `src/shared/i18n/index.ts` → `supportedLngs: ['ru', 'kk']`
  (это же показывает `LanguageSwitcher`).

Патч **не мержится** — он живёт только на время прогона. После — `git checkout`.
Автоматическая часть (см. ниже) этого не требует: тесты форсируют `kk` через
`i18n.use_locale("kk")` / `users.locale='kk'` / явный `locale="kk"`.

## Что уже покрыто автотестами

`pytest tests/integration/test_kz_e2e_smoke.py` (+ соседние `test_*_locale.py`,
`tests/guard/`) — прогоняется в CI гардом `i18n-guard.yml`:

| Поверхность | Тест |

| Все секции отчёта непусты и не являются i18n-ключом | `test_kz_e2e_smoke::test_report_has_no_empty_or_key_like_sections` |

## Ручная матрица (носитель языка, dev-стенд)

### 1. Онбординг и профиль

- [ ] Регистрация (2 шага), логин, Google-кнопка — подписи, ошибки валидации.
- [ ] Письмо-верификация приходит на `kk`; ссылка/код работают.
- [ ] «Забыли пароль» → письмо сброса на `kk` → новый пароль.
- [ ] Профиль-сетап: имя, возраст, класс, город, язык, предметы (чипы
      `SUBJECT_OPTIONS` — казахские подписи), сертификаты (IELTS/ҰБТ/SAT/TOEFL).
- [ ] Переключатель языка виден и переключает `ru`↔`kk` на лету.

### 2. Прохождение теста — все форматы экранов

Возрастные тиры × форматы (везде: заголовок, инструкция, варианты, кнопки,
прогресс, «привал» — на `kk`, без обрезки/переполнения):

- [ ] **junior** (MI + junior-пары): Harter-выбор, пары.
- [ ] **middle**: Ликерт, биполярная шкала, тройка-ранжирование,
      priority-ранжирование, пары, мотивация (Harter-пары).
- [ ] **senior**: Ликерт, биполярная шкала, тройка-ранжирование,
      priority-ранжирование, пары, мотивация (тройки).
- [ ] «Привалы» на 25 / 50 / 75 % — текст + подсказка «не торопись».
- [ ] Цели: `explore` / `profession` / `university`.
- [ ] Soft-downgrade: middle + `university` → `profession` (текст объяснения).
- [ ] Смена языка в середине теста (`ru→kk` и `kk→ru`) — прогресс не теряется,
      уже отвеченные экраны консистентны (KZ-406).

### 3. Отчёт `/results` — все секции

- [ ] Резюме (summary).
- [ ] Карта интересов: названия сфер + пояснение.
- [ ] Сильные стороны (карточки).
- [ ] Личность: заголовок, домены, статусы, пояснение.
- [ ] Стиль мышления: заметки.
- [ ] Мотивация: заголовок, драйверы, фразы.
- [ ] «Что попробовать сейчас».
- [ ] Вывод (final analysis).
- [ ] Профессии: карточки, «почему подходит».
- [ ] Форма обратной связи.
- [ ] Кнопка «Скачать PDF» → печатная версия (обложка, все блоки, next steps) на `kk`.
- [ ] Junior-вариант отчёта (другой подзаголовок / формулировки).

### 4. Профессия → вузы → программа

- [ ] Карточка профессии → детали направления (описание, навыки, предметы для
      развития, первые шаги) — на `kk`.
- [ ] Список вузов: страна/город в казахском написании (справочник `geo.ts`);
      бейдж «описание только на русском», если `description_locale != kk`.
- [ ] Страница программы: `description` + «для кого» на `kk` (после KZ-505);
      где перевода нет — транзитная плашка, не пустой блок.
- [ ] Gap-анализ: пункты требований, комментарии — на `kk`; `ҰБТ`, не `ЕНТ`.
- [ ] Стоимость обучения: формат чисел `kk-KZ`.

### 5. Не локализуется намеренно (проверить, что так и задумано)

- [ ] `/admin/*` — `ru`-only (KZ-210).
- [ ] Роадмап цели / роадмап направления, direction inquiry — dead code, не в
      проде, `kk`-часть не делалась (KZ-403/404).
- [ ] Сырые данные вузов: `exams` / `notes` / `grants` / официальные названия —
      остаются как есть (KZ-206), это не UI-копия.
- [ ] AI-генерация нарратива отчёта на реальном `kk`-ключе LLM — KZ-407,
      отложено (в проде до включения ключа работает детерминированный фолбэк,
      он на `kk`).

### 6. Регрессия `ru`

- [ ] Весь путь на `ru` байт-в-байт как до эпика (ни одна строка не изменилась
      из-за `kk`). Быстрая проверка — `test_result_locale::test_ru_owner_report_is_unaffected`
      + `pytest -k locale` целиком.

## Дефекты

Каждый найденный баг — отдельным тикетом со ссылкой на KZ-601 и указанием
экрана/эндпоинта из матрицы выше.
